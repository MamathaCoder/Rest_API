What is a REST API?

An API lets one program talk to another. A REST API does this over HTTP, the same protocol your browser uses. Everything is a resource (a user, a book, an order) with its own URL, and you act on it with standard HTTP methods.

The request and response cycle

CLIENT                              SERVER
  | GET /users/42  ------------------> |
  |                     finds user 42  |
  | <------ 200 OK {"name":"Asha"}     |

Every interaction is one request followed by one response.

Breaking down a URL

https://Scheme. Always prefer HTTPS.
api.example.comHost: the server.
/v1API version, so old clients keep working.
/users/42Path: the resource.
?status=shipped&limit=10Query: filters, sorting, paging.

HTTP methods

The method is the verb. The URL is the noun. Pick a method.

Status codes

Every response starts with a three-digit code. Memory trick: 2xx worked, 4xx you made a mistake, 5xx the server did.

Pick a code.
401 vs 403: 401 means “I don’t know who you are.” 403 means “I know who you are, but you can’t do this.”

JSON: the data format

Most REST APIs send and receive JSON, a lightweight text format built from key/value pairs.

{
  "id": 42,
  "name": "Asha",
  "isActive": true,
  "roles": ["admin", "editor"],
  "address": { "city": "Bengaluru", "country": "India" },
  "manager": null
}

Types: string, number, boolean, null, array [], object {}. Try it: type JSON below to check if it is valid.

Designing good endpoints


Use plural nouns. Let the method carry the verb.




✓ GET /books✗ GET /getAllBooks


✓ POST /books✗ POST /createBook


✓ DELETE /books/5✗ POST /deleteBook/5


✓ GET /authors/3/books✗ GET /booksByAuthor?id=3
